# asado-website

## Google review sync

The home page review cards are updated from `data/reviews.json`. The static review cards in `index.html` remain as the fallback if the generated file is empty, unavailable, or invalid in the browser.

`data/reviews.json` is generated by `.github/workflows/sync-google-reviews.yml`.

### Schedule

The workflow runs daily at `23 18 * * *`.

GitHub cron schedules use UTC, so this is:

- 06:23 in New Zealand Standard Time
- 07:23 in New Zealand Daylight Time

The workflow also supports `workflow_dispatch`, so it can be run manually from the Actions tab.

### Required GitHub Actions secrets

Configure these repository secrets in GitHub under Settings -> Secrets and variables -> Actions:

- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `GOOGLE_REFRESH_TOKEN`
- `GBP_ACCOUNT_ID`
- `GBP_LOCATION_ID`

Do not print these values in logs, issues, commits, or pull requests.

### Expected behaviour

- New valid Google reviews update `data/reviews.json`.
- No review changes are treated as a successful no-op and do not create a commit.
- Empty, malformed, or non-displayable API results fail the sync before replacing the last known-good review data.
- API failures fail the sync before replacing the generated file.
- Automated review-data commits use `[skip ci]`.

### Manual run and re-enable

To run manually, open GitHub -> Actions -> Sync Google reviews -> Run workflow.

If GitHub disables the workflow, open GitHub -> Actions -> Sync Google reviews -> Enable workflow. With GitHub CLI, run:

```powershell
gh workflow enable sync-google-reviews.yml
```

GitHub documents that scheduled workflows in public repositories can be disabled automatically after 60 days without repository activity:

- https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule
- https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows

Do not create meaningless commits just to keep the schedule alive. The preferred long-term fix is to move scheduling to the hosting platform or another reliable external scheduler and invoke a protected sync endpoint or build hook. A short-term fallback is to keep GitHub Actions, retain `workflow_dispatch`, and monitor the workflow externally so Samuel is alerted if it stops running.

### Local checks

This is a static site with no `package.json` or lockfile. The review sync uses built-in Node.js APIs.

```powershell
node scripts/test-sync-google-reviews.mjs
node scripts/sync-google-reviews.mjs --dry-run --fixture scripts/fixtures/google-reviews-valid.json
```
